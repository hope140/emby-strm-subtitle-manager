# SubBridge D1.5 最小只读 Web UI

D1.5 在现有 Go HTTP 服务中嵌入一个原生 HTML/CSS/JS 页面。页面与 `/v1/*` API 使用同一 Origin 和相对路径，仍由现有 request-id、安全头、no-store 和粗粒度路由日志中间件统一处理。

默认页面只提供以下只读操作：输入部署者配置的管理员用户名和密码、选择媒体库、浏览服务端既有的 Movie/Episode 混合分页、查看媒体详情和字幕清单。服务端为 UI 签发短期 `HttpOnly` 会话 Cookie；密码提交后立即从页面输入框清除，不进入 JavaScript 存储、URL、控制台或日志。CLI、定时任务和 CI 仍使用独立 Bearer Token，不在 UI 中输入。D2 后端开关仍默认关闭；只有 health 明确报告远程搜索启用、服务端 Canary allowlist 已生效且当前是单源 Movie/Episode 时，页面才额外显示 Search、候选 Fetch 与纯文本 Preview。它不提供 Save、下载、替换、删除、上传、刷新、批量扫描或其他写操作。D1.5 继续保持 `write_enabled=false`、`remote_search_enabled=false` 的默认值；D2 UI 的本地 Fake Emby 浏览器证据见 [D2-B2 UI 评审](d2-b2-readonly-ui-review.md)，管理员会话细节见 [D2.5 管理员认证](d2.5-admin-auth.md)。

详情页分别显示媒体上下文完整性和字幕清单完整性，并在多 MediaSource 时要求用户明确选择后重新读取。页面只显示 API 的安全投影，字幕文件名仅显示 basename，不显示 Provider ID、绝对路径、STRM 内部 URL 或认证信息。

## 使用边界

1. 内网、家庭 NAS、Tailscale 或 ZeroTier 网络中，可以直接使用 `http://IP:18080`。前提是服务监听地址和端口映射允许该内部网络访问；默认 Compose 示例只绑定宿主机 loopback，需要按实际私网拓扑调整。此方式适合受控网络，仍应限制可访问范围。
2. 公网 HTTP IP:端口在技术上保留，但不建议使用。Bearer Token 会在 HTTP 中明文传输，公网 HTTP 不等于安全。
3. 公网 HTTPS 是推荐方案，但不是所有用户的强制前提。公网 HTTPS 下，UI、`/assets/*` 和 `/v1/*` 必须同源；现有 OpenResty 根路径反代应原样转发这三类路径，并显式原样转发 `Authorization` 和 Cookie，同时使用安全日志格式且不记录 Authorization、Cookie、query 或完整请求路径。`security.session_cookie_secure` 应在 HTTPS 入口设置为 `true`。

本说明描述代码和配置边界，不代表任何真实 C92、SH 或其他部署环境已经完成 D1.5 验收。部署前仍需按实际环境单独验证证书、反代、访问控制和客户端行为。
