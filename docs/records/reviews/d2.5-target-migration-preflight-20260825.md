## 7. 后续轮换或回滚的最小顺序

后续轮换或回滚前，必须重新做实时检查，不能直接沿用本报告：

1. 确认目标 commit、镜像 digest、Compose/config 文件和旧镜像回滚点。
2. 由部署者在私有 Compose 的 app `environment` 中直接填入两个管理员变量；内容不进入公开示例、聊天、日志或 Git，并在启动前做变量存在性和格式预检。
3. 以当前公开 commit 构建不可变镜像，保留现有 closed D2 配置和恢复副本。
4. 只重建 app 服务，验证管理员登录、HttpOnly Cookie、Bearer 自动化、旧会话失效和失败限速。
5. 再从 C92 本机、SH 本机和 HTTPS 域名按路径验收；公网 18080 继续关闭。
6. 通过独立授权后，才考虑新的有界 D2 单源 Canary；D3 仍需另外的 scope、CSRF 和写入门禁。

## Knowledge Review

### Knowledge Findings

- 目标环境事实必须以实时容器标签和 `docker inspect` 为准，不能只依据 `LOCAL_OPERATIONS.md` 中的旧部署快照。
- XTerminal 的非交互 SSH MCP 已经可以直接提供 C92 命令通道；不需要通过桌面 UI 点击会话，也不应把 SH 与 C92 混用。
- Compose 版本化文件可能位于 `shared/`，预检必须从容器标签取得实际 `config_files` 和 `working_dir` 后再执行。
- D2.5 迁移前必须先识别其他会话已经留下的 D2 Canary、缓存和 allowlist，防止把新版本 Secret 误装到错误配置上。
- Compose file-source 的 `uid/gid/mode` 可能被 Docker Compose 忽略；配置文件必须用实际 UID 10001 容器执行 `test -r`，不能只看 YAML 元数据。
- env-only 管理员值可以留在 root-only 私有 Compose，非凭据 config 则要以宿主真实权限保证 app UID 可读；部署报告只记录路径、权限和非空门禁。
