# SubBridge 风险分级验收矩阵

本矩阵把日常开发验证、合并候选验证、真实环境 Canary 和正式发布验收分开。目标是在不弱化媒体写入、鉴权、路径安全和真实客户端读取门禁的前提下，避免同一证据在每次局部修改中重复获取。

## 使用规则

1. 先按本次改动的最高风险类别选择最低验收档；同时修改多类内容时取较高档。
2. CI 始终执行全量格式、`go vet`、`go test ./...` 和构建；开发者本地只需运行本次改动需要的最小检查集，合并前不重复手工执行 CI 已覆盖的无状态检查。
3. 真实 C92、Emby、Provider 和客户端证据只用于“能力首次启用、外部边界变更或正式发布”，不能由本地/Fake 结果替代，也不因纯本地改动自动失效。
4. 真正需要修改部署、重启、启用开关或写入媒体前，仍须取得用户明确授权，并先完成实时预检和可回滚记录。

## 验收档位

| 档位 | 触发改动 | 最小检查 | 不要求 |
|---|---|---|---|
| A 文档与元数据 | 文档、注释、非运行时配置说明 | Markdown 链接/UTF-8/代码围栏/尾随空白、`git diff --check` | Go 全测、浏览器、C92 |
| B 局部代码 | 单模块内部逻辑、非安全 UI 文案/展示，未改 API 或外部行为 | 受影响包测试；必要时静态检查或局部构建 | C92、真实客户端、全量浏览器 E2E |
| C 合并候选 | API/DTO、跨模块业务、认证/授权、缓存、路径、D3 恢复或 UI 流程变化 | `scripts/verify.ps1`；相关 Fake Emby 集成测试；相关本地浏览器 E2E | 部署或真实客户端，除非触发 D |
| D 能力 Canary | 首次启用某项能力；Emby/Provider 调用、Compose/镜像/挂载、PathMapper、写入语义、鉴权边界或代理边界变化 | C 全部；仅与变更边界对应的 C92 实时预检和 Canary；完成后恢复约定 closed 状态 | 不相关能力的重复 Canary |
| E 正式发布 | 打开面向用户的写能力、发布镜像/版本、升级路径或多个 D 类边界一起变更 | D 全部；覆盖 Movie、Episode、STRM 的代表性闭环；写操作验证 Hash、MediaStreams、字幕流、实际客户端读取及恢复 | 以文件存在或 Refresh 成功代替客户端读取 |

## 真实验收复用与失效条件

每项 D/E 证据必须登记在当前状态文档或对应验收报告中，至少写明能力、环境、镜像/提交、执行日期、闭环结果与恢复状态。以下变化才使同一能力的真实证据失效并重新触发 D 或 E：

- Emby、Provider、应用镜像、Compose/挂载、代理入口或权限模型变化；
- 影响 Item/source 绑定、PathMapper、字幕写入/恢复、鉴权、远程 Fetch 或客户端读取语义的代码变化；
- 切换目标环境、媒体映射、凭据来源或发布通道；
- 证据超过约定有效期，或运行态检查发现开关、版本、目录权限、健康状态与记录不一致。

纯文案、测试、内部重构、未改变外部契约的缺陷修复，不使真实 Canary 自动失效。若无法确定是否改变了外部语义，按更高一档处理。

## 能力台账

“当前状态与后续路线图”是当前能力台账的唯一入口；阶段报告只保存当次过程和证据。总体规划、ADR 和架构文档不重复记录实时提交、容器或开关状态。

每个待验收能力只保留一条待办：说明缺失的最小证据、触发条件和下一次合并执行的范围。禁止把同一个能力拆成单源、多源、UI 点击、部署、客户端读取等多个独立版本任务，除非安全边界或用户可见行为确实不同。

## Knowledge Review 的最小化

- A/B：在交付说明中写“检查范围、无新增长期知识”即可。
- C：仅当出现可复用约束、隐蔽坑或错误假设时填写完整模板并搜索去重。
- D/E：必须完成完整 Knowledge Review；真实环境边界、回滚经验和长期安全约束按文档职责分流。

Knowledge Review 不是额外验收档，不能重复要求已经由矩阵覆盖的测试或真实操作。
