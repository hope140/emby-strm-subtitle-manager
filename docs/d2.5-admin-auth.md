# D2.5 发布版管理员认证

状态：D2.5-A/B/C 已在本地实现并通过代码验证，A/B/D 已在 C92 完成 env-only app-only 验收；a70bf89 的完整 MediaSources 修正也已完成 app-only 重建和本机探针验收。C 的 scope 代码将在下一次 app-only 镜像发布时进入 C92；当前 C92 仍保持 D2/D3/写能力关闭。SH/FRP/OpenResty 未处理。目标环境记录见 [D2.5 目标环境迁移预检](d2.5-target-migration-preflight-20260825.md)。

本阶段把发布镜像的人机登录和自动化调用分开。普通管理员使用私有 Compose `environment` 提供的用户名和密码登录内嵌只读 UI；CLI、定时任务和 CI 继续使用独立 Bearer Token。当前仍是单实例、单管理员模型，不提供注册、改密码、注销、找回密码、用户列表或多角色后台。

## 配置契约

发布版 Compose 的 app 服务必须直接提供两个固定环境变量。公开示例保留空占位符，实际部署文件由部署者填入值：

```yaml
services:
  app:
    environment:
      APP_ADMIN_USERNAME: ""
      APP_ADMIN_PASSWORD: ""
```

应用配置只保留会话参数：

```yaml
security:
  session_cookie_secure: false
  session_ttl_seconds: 28800
```

- `APP_ADMIN_USERNAME` 和 `APP_ADMIN_PASSWORD` 缺失或为空时，服务启动失败。
- 用户名长度为 1–64 字节，不接受首尾空白、空白字符或控制字符。
- 密码长度为 6–256 字节，不接受控制字符；密码可以包含空格。
- 管理员密码不能复用 Emby API Key、应用 Bearer Token 或 identity secret（包括 identity 的标准 Base64 形式）。
- 环境变量值不能包含控制字符或多行内容；没有默认账号密码，也不自动生成。
- 两个变量必须同时存在。应用不会回退到 Bearer-only UI；缺少或非法值直接阻止启动。

密码只在启动时从环境读取，进程内保存带随机盐的 PBKDF2-HMAC-SHA256 派生校验材料，不写入配置、镜像、Git、日志、URL 或响应。轮换方式是修改私有 Compose 的两个 environment 值并重建容器；重建也会让所有旧会话失效。Docker 主机管理员仍应限制 Compose 文件和容器元数据的读取权限。

## HTTP 会话

`POST /v1/auth/login` 是唯一不需要先认证的 `/v1` 路由，只接受无 query 的 JSON 用户名和密码。成功后返回不含凭据的状态 JSON，并设置：

- Cookie 名称 `emby_strm_admin_session`
- `HttpOnly`
- `SameSite=Lax`
- `Path=/`
- 默认 8 小时固定 TTL，可配置范围为 60 秒至 24 小时
- `security.session_cookie_secure=true` 时增加 `Secure`，公网 HTTPS 应开启它；内网 HTTP 示例保留 `false`

会话只保存在内存，服务重启后全部失效；服务端只保存会话 Token 的 SHA-256 摘要。登录失败按服务端观察到的远端地址做有界限速：5 分钟内 5 次失败后锁定 1 分钟，状态表和会话表都有固定上限。错误响应不回显用户名、密码、Cookie 或上游内容。

所有其他 `/v1/*` 路由都接受有效管理员会话 Cookie 或 `Authorization: Bearer <token>`。Bearer 仍然只用于自动化，拒绝 query token，并按 `security.api_auth_scopes` 做只读 scope 检查：媒体浏览和健康路由需要 `media:read`，Search 需要 `subtitle:search`，Fetch/Preview 需要 `subtitle:preview`。有效 Bearer 缺少所需 scope 时返回 `403 insufficient_scope` 和标准 `WWW-Authenticate` 参数；错误或缺失 Bearer 仍返回 401。`subtitle:write` 是预留 scope，在 `write_enabled=false` 时会被配置校验拒绝，当前不能把 Bearer 宣称为 D3 写入权限系统。

公开配置未填写 `api_auth_scopes` 时使用完整的只读集合。部署者可以删除只读 scope 进一步限制自动化，但不能通过配置授予写 scope；管理员 HttpOnly 会话只覆盖当前只读路由，未来写路由必须另行检查 scope 和 CSRF。

## UI 行为

页面只显示管理员用户名和密码输入框。密码在提交后立即清空，JavaScript 不读取或写入 `localStorage`、`sessionStorage`、可读 Cookie、URL、DOM `data-*` 属性、控制台或日志。页面不提供注销或改密按钮；重新加载页面会回到登录界面，服务端会话仍受固定 TTL 控制。会话过期时 API 的 401 会把页面重新切回登录界面。

D2 Search、Fetch、Preview 仍是只读、默认关闭、单源 fail closed 的原有契约；管理员会话不会扩大 D2 能力，也不会打开 `write_enabled`。

## Knowledge Review

任务或阶段：D2.5-A/B/C 发布版管理员认证、会话与只读 scope。

验证范围：`internal/auth`、`internal/config`、`internal/httpapi`、内嵌 UI、Fake Emby 浏览器流程、Compose 示例和脱敏日志。

Knowledge Findings：

- 新增约束：管理员人机登录使用 HttpOnly 会话；自动化保留独立 Bearer，二者不共用输入界面或凭据。
- 隐蔽坑：浏览器 JavaScript 看不到 HttpOnly Cookie，因此 E2E 的 `document.cookie` 为空不能证明服务端没有会话；必须同时检查 Set-Cookie 属性和带 Cookie 的 API 请求。
- 被证明错误的假设：旧的“UI 只在内存保存 Bearer”描述已不适用于发布版，UI 现在不接收 Bearer。
- 建议沉淀项：登录失败限速和会话上限必须保持有界；管理员 environment 只存在私有 Compose，不进入公开示例或日志。

- `docs/lessons-learned.md`：更新管理员会话/HttpOnly 与 E2E 证据边界。
- `docs/architecture.md`：更新认证数据流和当前路由事实。
- `docs/adr/`：ADR-006 保留为方案 C 的长期决策，补充管理员会话和只读 scope 实现状态；CSRF 与 D3 写入仍未接受。
