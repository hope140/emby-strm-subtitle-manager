# D1.5 部署前预检清单

状态：代码和本地验收已准备，尚未执行 C92、SH、FRP、OpenResty 或其他真实环境部署。

本文是 D1.5 发布前的可执行预检清单。它只覆盖同一 Go 服务内嵌的最小只读 UI，不授权修改远端配置、重启容器、重载反代或发布镜像。

## 1. 发布不变量

部署候选必须同时满足以下条件：

- `features.write_enabled=false`
- `features.remote_search_enabled=false`
- UI 只有媒体库、Movie/Episode 分页、详情和字幕清单浏览；没有搜索、下载、Fetch、预览、替换、删除、上传、批量扫描或其他写操作
- UI、`/assets/*` 和 `/v1/*` 使用同一 Origin；反代原样转发 `Authorization` 和管理员会话 Cookie
- UI 使用私有 Compose `environment` 配置的管理员用户名和密码登录，固定变量名为 `APP_ADMIN_USERNAME`、`APP_ADMIN_PASSWORD`；密码提交后清除，不进入 URL、query、localStorage、sessionStorage、可读 Cookie、控制台、响应或日志
- 管理员会话为 `HttpOnly`、`SameSite=Lax`、固定 TTL；公网 HTTPS 部署必须将 `session_cookie_secure=true`，HTTP 仅限受控内网
- 媒体目录以只读方式挂载，应用以 UID/GID `10001:10001` 运行，并保持 `read_only: true`
- Emby API Key、应用 API Token 和 identity secret 使用三个不同的受保护文件
- 仓库、镜像构建上下文、测试夹具、截图和日志不包含 Secret、私有路径、媒体标题或 Item ID

## 2. 当前准备结果

本轮已经完成的本地准备：

- Go 格式检查、`go vet ./...`、带 `-count=1` 的单元测试和服务构建
- 前端 `app.js` 语法检查
- `git diff --check`
- 使用合成 Fake Emby 数据的真实浏览器流程：管理员用户名/密码登录、媒体库、Movie/Episode 分页、多源选择、详情、字幕清单、映射和两类完整性状态
- 浏览器刷新后回到登录页；JavaScript 可见的 localStorage、sessionStorage、document.cookie 均为空，服务端 HttpOnly 会话不被页面脚本读取。多源详情首次请求按设计返回一次 HTTP 409 并进入媒体源选择分支；除这一预期响应外，最终浏览器控制台无异常告警或错误
- OpenResty 示例显式转发 `Authorization` 和管理员 Cookie，安全日志示例不记录完整请求行、query、Cookie 或认证头

- 本轮没有修改或重启 C92、SH、FRP、OpenResty，也没有进行公网客户端验收
- 真实多媒体源样本仍未补齐；按 [ADR-005](adr/005-conditional-d2-entry-without-live-multisource.md)，它继续阻断多源搜索支持声明和启用，但不再阻断 D2 契约、实现和单源 Canary
- D1.5 代码与本地自动化验收已收口；部署候选仍需以当次提交、CI 和不可变镜像为准，不能把未重新部署的工作区当作线上版本

## 3. 三种访问方式

| 方式 | 支持边界 | 部署前必须确认 |
|---|---|---|
| 内网、家庭 NAS、Tailscale、ZeroTier：`http://IP:18080` | 支持在受控私网或覆盖网络内直接访问 | 宿主机端口必须绑定到实际可达的私网/覆盖网络接口，并由主机防火墙限制来源；通用 Compose 示例默认只绑定宿主机 loopback，不能直接被其他设备访问 |
| 公网 HTTP IP:端口 | 技术上保留 | 明确标记为不建议；Bearer Token 在 HTTP 中明文传输，不能作为推荐公网方案 |
| 公网 HTTPS | 推荐方案，不是所有用户的强制前提 | UI、`/assets/*`、`/v1/*` 同源；证书严格校验；HTTP 到 HTTPS 的策略、`Authorization`/Cookie 转发、安全日志和应用端口隔离均需在真实入口验收 |

直接私网访问与公网 HTTPS 是两种不同拓扑。不要把 host-network 示例的 loopback 配置、通用 bridge 示例的端口绑定和反代入口混用；先选定一种拓扑，再分别核对监听地址、端口映射、PathMapper 和防火墙。

## 4. 部署目录与配置准备

在目标主机建立仅供部署使用的目录，并从仓库复制以下模板。实际目录名和媒体路径只留在目标主机，不回写仓库：

```text
compose.yaml                         # 选定 bridge 或 host-network 示例
config.yaml                          # 由 config.example.yaml 或 host-network 模板复制
secrets/emby_api_key                 # Emby API Key
secrets/app_identity_key             # 独立 identity secret
secrets/app_api_auth_token           # CLI/自动化使用的 Bearer Token
Compose environment: APP_ADMIN_USERNAME # Web UI 管理员用户名
Compose environment: APP_ADMIN_PASSWORD # Web UI 管理员密码
secrets/d2_canary_items              # 仅合并 D2 overlay 时准备
```

准备配置时逐项确认：

1. `emby.url` 是目标环境中应用可达的 Emby 地址，并使用适合该拓扑的协议和端口。
2. `path_mappings.emby` 与 Emby 实际报告的媒体根路径完全一致，`local` 保持为容器内的 `/media`。
3. 媒体源绑定到 `/media` 且为只读；不能把宿主机 Secret、Docker socket 或其他无关目录挂进容器。
4. `security.identity_key_file` 和 `security.api_auth_token_file` 继续指向 `/run/secrets/` 下的两个服务端文件凭据；Compose `environment` 必须同时直接提供 `APP_ADMIN_USERNAME`、`APP_ADMIN_PASSWORD`。
5. 三个服务端文件凭据与管理员 environment 值互不复用；管理员密码至少 6 字节，不使用仓库默认值。公开示例只保留空占位符，私有 Compose 才填入实际值。
6. 内网 HTTP 可将 `session_cookie_secure=false`；公网 HTTPS 必须设为 `true`。
7. `write_enabled` 与 `remote_search_enabled` 仍为 `false`，不要因 UI 登录成功而放宽开关。

D2 若获得单独授权才可启用，部署材料必须提前保留以下边界：

- `d2.cache_dir` 使用容器内的 `/var/lib/emby-strm-subtitle-manager/d2-preview-cache`；只有 D2 Canary overlay 才为这个精确目录增加可写 bind mount。宿主 source 必须是专用目录，例如 `/replace/with/dedicated/d2-preview-cache`，与媒体 source 不相同，也不能位于媒体根、媒体祖先或媒体子目录中。
- 启动前在宿主机实际创建并核对该专用目录：owner 为 `10001:10001`、mode 为 `0700`。`read_only: true` 的 rootfs 和 `/media` 只读挂载继续保留；不能把 `/var/lib`、宿主媒体根或其他宽目录作为可写挂载。
- Canary allowlist 由 `./secrets/d2_canary_items` 作为新增 file-source Secret 注入到容器 `/run/secrets/d2_canary_items`，配置中的 `d2.canary.item_allowlist_file` 必须与之相同。宿主机实际设置 owner `10001:10001`、mode `0400`，并在容器内用应用用户做可读性预检；Compose 的 `uid`、`gid`、`mode` 字段只作兼容性提示，不能替代宿主机文件权限核对。allowlist 每行一个精确 Item ID，不得进入 Git、日志或响应。
- 只有 D2 Canary overlay 声明该 file-source，因此默认 D1 Compose 不需要创建 D2 目录或 Secret。使用 overlay 时，`./secrets/d2_canary_items` 必须存在；D2 关闭时可使用 owner `10001:10001`、mode `0400` 的空占位文件，只有获得授权后才填入非空精确 allowlist。`remote_search_enabled=true` 时空文件会被配置门禁拒绝。
- 缓存只保存短期 Artifact，属于可丢弃数据。回滚时先停止目标应用，保留上一份镜像、配置和 allowlist 备份；若要清理，只能在确认解析后的精确专用 cache source 后清理其 Artifact 文件或整个专用目录，不能对父目录、媒体 source 或 compose 工作目录做递归清理。bind mount 数据不会因 `docker compose down` 自动删除，避免用宽泛的 volume 清理命令误触其他数据。

不要把真实配置、Secret 文件、含认证参数的 URL、浏览器导出的存储数据或真实 Item 数据复制回仓库。

## 5. 目标主机的无写入预检

以下命令只做配置、文件可读性和镜像元数据检查，不输出凭据内容。管理员值只存在目标主机的私有 Compose `environment`，不使用 `.env`，不写入仓库：

```sh
docker compose config --quiet
docker compose config --images

# D2 默认关闭时，使用 base Compose，不需要 D2 cache/allowlist 文件：
docker compose -f compose.example.yaml config --quiet

# 仅在获得 D2 Canary 授权并准备专用目录/allowlist 后，显式合并 overlay：
docker compose -f compose.example.yaml -f compose.d2-canary.example.yaml config --quiet
docker compose -f compose.host-network.example.yaml -f compose.d2-canary.example.yaml config --quiet

docker compose run --rm --no-deps --entrypoint sh app -c \
   'test -r /run/secrets/emby_api_key && \
   test -r /run/secrets/app_identity_key && \
   test -r /run/secrets/app_api_auth_token && \
   test -r /etc/emby-strm-subtitle-manager/config.yaml'

# 仅在获得 D2 授权并准备非空 allowlist 后追加：
docker compose run --rm --no-deps --entrypoint sh app -c \
  'test -r /run/secrets/d2_canary_items'

docker image inspect "$IMAGE_REF" --format \
  '{{index .Config.Labels "org.opencontainers.image.version"}} {{index .Config.Labels "org.opencontainers.image.revision"}} {{index .Config.Labels "org.opencontainers.image.created"}} {{index .Config.Labels "org.opencontainers.image.source"}}'
```

检查结果应同时证明：Compose 能解析、镜像引用是预期的不可变版本、三个服务端文件凭据与配置文件能被应用用户读取，且两个管理员 environment 已直接设置并通过启动校验；D2 授权时还要证明 allowlist Secret 可读、专用 cache bind source 已按 `10001:10001`、`0700` 创建且不是媒体 source 的祖先/子目录。预检失败时保持现状，不启动新版本。

正式部署应使用不可变发布标签或镜像摘要，并记录上一份已验收的镜像引用。不要用 `local`、`latest` 或其他浮动引用覆盖线上版本。

## 6. 启动后的最小验收顺序

启动、重建或 reload 需要目标环境负责人明确授权。本节只规定验收顺序：

1. 访问 `/livez`，确认进程存活；访问 `/readyz`，确认 Emby 只读探测成功。
2. 对 `/v1/health` 和业务 API 分别验证无凭据、错误 Bearer、query Token 均为 401；登录接口验证错误用户名/密码的 401、限速 429 和正确凭据的 HttpOnly Cookie；正确管理员会话或 Bearer 才能得到预期只读响应。
3. 打开 `/`，确认页面和 `/assets/*` 由同一 Origin 提供，响应包含既有安全头和 UI CSP。
4. 在浏览器中输入测试管理员用户名和密码，依次验证媒体库、Movie/Episode 分页、详情、字幕清单、映射状态、媒体上下文完整性和字幕清单完整性；确认密码提交后输入框清空，刷新后回到登录界面。
5. 对多 MediaSource Item 验证页面先显示选择状态，用户选择后才读取对应详情；不得默认猜测第一 source。
6. 通过实际客户端网络路径重复一次流程。内网模式验证 `http://IP:18080`；公网模式验证 HTTPS 证书、同源 API、HTTP 处理策略和应用 remote port 的公网不可达性。
7. 检查应用、OpenResty、FRP 和主机日志不包含 Authorization、Token、query、完整请求路径、原始 Item ID、候选 ID、媒体标题或私有路径。
8. 验收结束后关闭浏览器页面并清理浏览器会话；不要导出 Cookie、浏览器存储或 Secret 作为排障附件。

真实多媒体源样本的完整性和多源验收另按 D1/D2 门禁执行，不能用合成 Fake Emby 浏览器测试替代。C92 已补齐一个真实版本组，`AlternateMediaSources` 客户端字段修正和回归测试已在本地完成，但 API/UI/source 对应验收仍待完成；按 ADR-005，多源搜索必须安全拒绝，直到完整门禁通过。

## 7. 回滚准备

回滚前应已经保存：

- 上一份已验收的不可变镜像标签或摘要
- 当前 `config.yaml`、三个基础文件凭据和可选 D2 allowlist Secret 的受控备份位置；管理员 environment 只记录变量名，不记录值
- 专用 D2 cache bind source 的准确路径及其与媒体 source 不 overlap 的核对结果；该目录是可丢弃 Artifact 数据，不是媒体备份
- 当前镜像摘要、配置校验结果和验收时间
- 目标主机上可以恢复的 Compose 文件版本

D1.5 没有数据迁移，且应用 rootfs 与媒体目录保持只读。若验收失败，停止继续扩大访问范围，按原 Compose 拓扑恢复上一份镜像引用，再重新执行 `/livez`、`/readyz`、管理员登录、Bearer 认证和真实客户端路径检查。D2 回滚只切换已验收的镜像/配置；需要清理时先停止应用，只处理已核对的专用 cache bind source，不能递归删除其父目录、媒体目录或整个部署目录。bind source 不因 `docker compose down` 自动删除，allowlist 备份也不随缓存清理删除。回滚命令不在本轮执行。

## 8. 本轮结论

代码层和浏览器层的 D1.5 准备已完成，部署材料、三种访问边界、Secret 角色、不可变镜像和回滚要求已经明确。本文没有重新核对目标主机的 Docker/Compose 状态或真实 C92/SH 入口，任何后续部署仍需按当次目标环境验收。真实多媒体源样本继续作为多源搜索支持门禁；它不阻断单源 D2。没有明确部署授权时，现有运行环境保持不变。
