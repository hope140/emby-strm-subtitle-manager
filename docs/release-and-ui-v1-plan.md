# 发布收口与 UI/V1 计划

## 状态与前提

Core A/B 的单源 STRM 日常闭环已经完成：真实管理 UI 的 Search、Fetch、Preview、Add、Upload、Replace、可恢复 Delete、Restore 以及实际播放器字幕显示均已在受控窗口验证，窗口结束后已恢复 closed 状态。

本计划不把该结论扩展为普通本地媒体、多源 STRM 写入或批量自动化。它们仍是独立边界。

## 当前执行决定

M0 暂缓，不作为 UI/V1 的当前阻断项。当前 C92 已验证最新 Core 行为并恢复 closed；正式镜像、全新环境安装和公开分发在 UI/V1 稳定后统一完成。下一项开发工作直接进入 M1。

## 顺序

### M0　核心测试版发布收口（暂缓）

目标是把已验证的 Core 能力变为可安装、可回滚、可追溯的测试版，而不再增加媒体写入语义。

- 从精确 Git 提交构建镜像，固定 OCI revision、版本和摘要。
- 保留上一已验收镜像、closed Compose 和回滚步骤；默认保持远程搜索、写入和媒体挂载只读。
- 编写安装、升级、回滚和首次管理员配置说明；示例不包含凭据或私有路径。
- 在全新环境完成最小安装验收：启动、登录、健康端点、鉴权、默认 closed 状态和只读媒体边界。

通过条件是新环境可重复安装和回滚，且运行镜像可追溯到精确 Git 提交。它不要求重复已经通过的单源写入闭环。

### M1　UI/V1 只读信息架构

先改善浏览和理解，不改变 Core 的 Item/source/写入契约。

- 媒体库、类型、剧集、季、集和版本的层级导航。
- 每个明确 Item/source 的字幕清单、语言、格式、来源、可管理性、写能力和安全 warning 展示。
- 统一空状态、加载状态、错误码的中文行动提示和窄屏布局。
- 保持路径、原始候选 ID、Token、Cookie 和凭据不进入页面、URL 或浏览器存储。

通过条件是现有只读和 Core 操作在新导航下仍保持显式 source 选择与原有安全边界。

### M2　UI/V1 操作与可观测性

在 M1 稳定后补充操作体验，不把服务端密配置搬进浏览器。

- Provider 状态页，仅展示脱敏、可行动的 Provider/候选状态。
- 操作历史和恢复的筛选、结果摘要与稳定错误说明。
- 只读运行设置摘要和脱敏日志查看；凭据、路径、令牌和可写开关仍只能由服务器部署配置控制。
- 对 Add、Replace、Delete、Restore 保留明确确认、异步状态、可恢复性提示和刷新后的结果核验。

通过条件是所有新 UI 入口仍通过既有管理员会话、CSRF、scope 与服务端 resolver，不产生前端路径信任或新的写入通道。

### M3　V1 安装体验与正式发布

- 选择正式版本号并发布签名/摘要可核验的镜像。
- 完成新用户安装、升级、回滚和故障排查文档。
- 在干净环境执行端到端安装验收；真实写入仅在单独授权的受控样本上执行。

## 独立边界验收

以下工作不阻塞 M1 的只读 UI，但在宣称对应能力前必须单独验收：

| 边界 | 需要证明的结论 |
|---|---|
| 普通本地 Movie/Episode | 选中本地 MediaSource.Path 的 Search→Preview→写入→MediaStreams→客户端读取不会串写版本。 |
| 多源 STRM | Search/Fetch/Preview 可用；Add、Replace、Delete、Restore 稳定返回 `409 strm_multisource_write_unsupported` 且无媒体变更。 |
| 自动化能力 | 缺字幕筛选、批量任务、自动下载、评分和时间轴校正另立计划，不并入 UI/V1 首批。 |

## 非目标

- 不在 UI/V1 中实现批量写入、自动下载、永久删除或浏览器端密钥配置。
- 不根据标题、默认 source 或列表顺序猜测写入目标。
- 不将多源 STRM 的共享 sidecar 设计成 source-specific 可管理文件，除非取得新的 Emby 关联证据并通过 ADR。
